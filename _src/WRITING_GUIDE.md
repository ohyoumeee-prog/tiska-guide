# 티스카 굿즈 제작 가이드 — 글쓰기·발행 규칙 (매일 3편 자동 발행용)

이 문서는 블로그(https://ohyoumeee-prog.github.io/tiska-guide/)에 글을 쓰는 사람(사람이든 AI든)이 지켜야 할 규칙입니다. 자동 발행 루틴은 매일 이 문서를 먼저 읽고 글 3편을 씁니다.

## 1. 사실의 출처(여기 없는 숫자는 쓰지 않는다)
- `_src/FACTS.md` — 최소 수량·샘플·양산 기간(품목군 10개 표), 진행 순서, 가공 목록, 공개 실적(사례 167건·고객사 42곳), 연락처. **유일한 숫자 출처.**
- `_src/cases_data.tsv` — tiska.kr 공개 제작 사례(제품 138건 type=p, 포트폴리오 29건 type=f). 열: type, no, title, lead, 업종, 클라이언트, 품목, 소재, 도금, 가공, 용도, 최소 수량, 샘플, 양산, 프로젝트, 제작 품목, 품목 수. 사례를 인용할 때는 이 표의 클라이언트·품목·소재·가공·용도를 그대로 쓴다. 제품 사례 주소: `https://tiska.kr/board/magazine/read.html?no={no}&board_no=5`, 포트폴리오: `https://tiska.kr/board/gallery/read.html?no={no}&board_no=8`.
- 기존 글 `_src/content/*.md` — 톤과 형식의 기준. 같은 주제를 다시 쓰지 않는다(제목·슬러그가 `_src/posts.tsv`에 있으면 중복).
- 단가·비용 숫자는 절대 쓰지 않는다. "수량 구간별 단가는 견적 시 안내"로만 쓴다. 날짜 계산은 FACTS의 기간을 더한 예시로만 쓴다.

## 2. 반드시 지킬 문구 규칙
- 최소 수량은 **"메인 발주 500개부터"** 로만 표현한다(한 줄 답변 첫 문장에 반드시 포함). "500개 단위·500개씩·배수" 금지. 옛 수치(10·50·100·300개부터) 금지.
- 부정형 표현 금지: 받지 않는다, 어렵다, 불가, 인력 부족, 대응이 어렵다. 안내형으로 바꿔 쓴다("~는 견적 시 함께 상담합니다").
- 500개 미만 안내는 이 한 문장만, 글당 최대 2회: "500개 미만의 소량이 필요하면 자체 소량 제작 쇼핑몰 나도메이커(nadomaker.com)에서 제작할 수 있습니다."
- 금지어: 판촉물(→ 프로모션 제품·기념품·사은품), 직원 개인 이름, 최저가, 업계 1위, 국내 유일, 최고, 보장.
- 클라이언트명은 cases_data.tsv의 공개 표기만. 특정 대회명·행사명·고객 문의 내용·경쟁사명을 지어내지 않는다. 문의가 늘고 있다는 말은 "최근 ○○ 문의가 늘고 있습니다" 정도의 일반 표현까지만.
- 티스카를 홍보하되 근거로 말한다: 공개 사례, 품목군 표, 진행 6단계, 자체 공장 + 광저우·이우 생산 네트워크, 전담 PM, 승인 샘플 기준 양산.

## 5. 발행 절차(자동 루틴·사람 공통)
1. `_src/content/NN_주제.md` 3개 작성.
2. `_src/posts.tsv` 에 3줄 추가: `NN<TAB>파일명<TAB>슬러그<TAB>독자<TAB>짧은 이름(빵부스러기용, 10자 안팎)<TAB>YYYY-MM-DD<TAB>HH:MM` (시각은 09:00, 09:20, 09:40처럼 발행 순서대로).
3. `bash _build/publish.sh "가이드 글 3편 추가(YYYY-MM-DD): 제목1 / 제목2 / 제목3"` 실행 → 빌드 → 규칙 검사 → 커밋·푸시. 검사에 실패하면 지적된 문장을 고치고 다시 실행한다.
4. `_src/publish_log.md` 맨 아래에 `- YYYY-MM-DD | 슬러그1 / 슬러그2 / 슬러그3 | 커밋 해시` 를 적는다(publish.sh 실행 전에 적어 두면 같은 커밋에 들어간다).
4-1. 보고서: `_src/reports/YYYY-MM-DD.md` 에 글마다 제목·주소·독자·3문장 요약·사용 사례(TSV no)·고친 점, 내일 후보 주제 3개, 특이사항을 적는다(루틴 프롬프트 8번).
5. 공유 이미지(og/슬러그.png)는 없으면 og/default.png 가 자동으로 쓰인다. 로컬(Windows)에서는 `powershell -ExecutionPolicy Bypass -File og.ps1 -Dir <저장소 경로>` 로 만들 수 있다.

## 6. 제작 사례 글(매일 1편, 사장님 확인 후 발행)
- 출처: `_src/cases_data.tsv`의 한 행(no). 사진은 `posts/img/` 에 있는 파일(p_{no}_{nn}.jpg = 제품 사례, f_{no}_{nn}.jpg = 포트폴리오 사례)만 쓴다. 사진이 없는 사례는 쓰지 않는다.
- 승인 절차: 초안은 `_src/case_queue.tsv`(열: no, type, client, item, status, slug, file, images, drafted, published, note)에 status=draft 로 올리고 사장님께 보여 드린다. 사장님이 확인하면 status=approved, 발행되면 status=published(날짜). 자동 발행 루틴은 approved 인 사례만 하루 1편 발행한다.
- 초안 파일 위치: 사장님이 확인하기 전의 초안(.md)과 미리보기(.html)는 저장소에 올리지 않는 로컬 폴더 `_src/drafts/`(.gitignore)에 둔다. case_queue.tsv의 file 열은 draft 행은 그 경로(_src/drafts/…), approved·published 행은 파일명만(`_src/content/` 안에 있음)으로 적는다. 승인되면 파일을 `_src/content/`로 옮기고 file 열을 파일명만으로 고친 뒤 status=approved 로 커밋·푸시한다. 루틴은 `_src/content/`에 있는 approved 사례만 발행한다.
- posts.tsv 행: `n`은 `C01`, `C02`… 처럼 C 번호(가이드 글 번호와 별개), `kind` 열에 `case`, `short`는 "클라이언트 품목"(예: 기아자동차 연말 패키지), 발행 시각 10:00.
